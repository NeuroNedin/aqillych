# CRM в Telegram

Мини-апп внутри Telegram плюс бот, который ведёт базу потенциальных клиентов.
Можно кинуть боту список людей сообщением — они попадут в очередь «Кому написать».
Каждое утро бот сам напоминает, кому сегодня написать.

Всё живёт на Cloudflare Workers: одна программа отдаёт и страницу мини-аппа,
и принимает сообщения бота, и хранит базу. Бесплатного тарифа хватает с запасом.

## Что умеет

**Мини-апп** — две вкладки.

- **Кому написать** — все, кому ещё не отправлял первое сообщение,
  сгруппированы по источнику. Нажал «Написал» — человек уходит во вторую
  вкладку, а следующее касание назначается через заданное число дней.
- **В работе** — план недели, кого коснуться сегодня, вся база с поиском
  и фильтрами. Там же кнопка «Настроить».

**Настройки** (у каждого свои)

- Цели недели: партнёры, холодные, созвоны, предоплаты. Ноль скрывает строку.
- Через сколько дней напоминать после «Написал».
- Час утренней сводки и часовой пояс.

**Бот**

- Пришли список сообщением — заведёт карточки и даст отменить одной кнопкой.
- `/today` — просрочки, касания на сегодня, размер очереди, план недели.
- `/plan` — прогресс по недельным целям.
- Каждое утро присылает сводку сам, в назначенный час по своему поясу.

**Доступ.** Бот закрытый: чтобы начать, человек присылает код приглашения.
База у каждого своя — чужих контактов не видит никто, и один и тот же
эксперт может быть в базах у разных людей.

Команды владельца (того, чей номер в `OWNER_ID`):

- `/invite` — выдать код на одного человека
- `/invite 5 курс Шамси` — код на пятерых с пометкой
- `/people` — кто пользуется и какие коды ещё свободны
- `/revoke <код>` — отозвать невыданный код

**Формат списка** — один человек на строку:

```
Ахмад — @ahmad_arabic — преподаёт арабский
Иса | t.me/isa_coach | тренер по борьбе
@yusuf_finance
Марьям — нутрициолог
```

Разделители: тире, `|`, `;`. Порядок «имя — контакт — ниша» не обязателен:
ссылка и `@ник` узнаются в любом месте строки. Если в строке только ник —
он же станет именем. Повторы отсеиваются: `@ivan`, `t.me/ivan` и
`https://t.me/ivan/` — один и тот же человек.

## Установка

Нужны два бесплатных аккаунта: [Telegram-бот](https://t.me/BotFather) и
[Cloudflare](https://dash.cloudflare.com/sign-up). Таблицы в базе Worker
создаёт сам при первом запросе — вручную ничего выполнять не нужно.

### Без командной строки, из браузера

Годится и с телефона.

1. **Бот.** [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя.
   В ответ придёт токен вида `123456789:AAF...`.
2. **Свой Telegram ID.** [@userinfobot](https://t.me/userinfobot) ответит числом.
3. **База.** В панели Cloudflare: раздел с хранилищами → **D1** → создать базу
   с именем `crm`. Скопируй её `Database ID` и впиши в `wrangler.toml`
   вместо нулей (файл можно отредактировать прямо на GitHub).
4. **Worker.** В панели Cloudflare: **Workers** → импортировать репозиторий →
   выбрать этот репозиторий и ветку. Cloudflare соберёт и выложит сам,
   а `wrangler.toml` из репозитория подхватится вместе с привязкой к базе.
5. **Секреты.** В настройках Worker'а → переменные → добавь две штуки
   **как Secret**: `BOT_TOKEN` и `OWNER_ID`.
6. **Вебхук.** Нужен `secret_token` — он выводится из токена бота,
   так что задавать его отдельно не надо. Проще всего собрать ссылку
   на [странице установки](https://claude.ai/artifact/SEE1j2EZfPWCBV4TcKiAoB)
   и открыть её: в ответ должно прийти `{"ok":true,...}`.
7. Напиши боту `/start`.

### Через командную строку

Понадобится [Node.js](https://nodejs.org) 20 или новее.

```bash
git clone https://github.com/NeuroNedin/aqillych.git
cd aqillych
npm install
npx wrangler login
npx wrangler d1 create crm      # id из ответа впиши в wrangler.toml
npx wrangler secret put BOT_TOKEN
npx wrangler secret put OWNER_ID
npm run deploy                  # напечатает адрес Worker'а
```

Затем одной командой ставятся вебхук, команды бота и кнопка меню:

```bash
BOT_TOKEN=токен APP_URL=адрес npm run bot:setup
```

## Настройки

В `wrangler.toml`, блок `[vars]`. После изменения — `npm run deploy`.

| Переменная    | Что значит | По умолчанию |
|---------------|------------|--------------|
| `TZ_OFFSET`   | Часовой пояс для тех, кто ещё не открывал настройки. Ташкент — `300`, Москва — `180` | `300` |
| `DIGEST_HOUR` | Час утренней сводки по умолчанию, 0–23 | `9` |
| `APP_URL`     | Адрес мини-аппа. Обычно пусто: Worker запоминает свой адрес сам | пусто |

Цели, дни напоминания и время сводки каждый меняет сам в приложении.
Значения по умолчанию для новичков, а также статусы и источники лежат
в `src/domain.js` и `src/schema.js`.

## Как устроено

```
src/
  index.js    маршруты: API мини-аппа, вебхук бота, ежечасный cron
  auth.js     проверка подписи Telegram — без неё в базу не пустят
  bot.js      разбор сообщений, тексты ответов, утренняя сводка
  db.js       запросы к базе и проверка всего, что в неё кладут
  parse.js    разбор списков и приведение контактов к единому виду
  domain.js   статусы, источники, строки плана, работа с датами
  schema.js   структура базы
  migrate.js  приведение базы к текущей схеме при первом запросе
public/
  index.html  страница мини-аппа
  app.js      её логика
```

Мини-апп сам ничего не решает: сервер отдаёт ему готовые данные вместе
со словарями статусов и ссылками на контакты. Поэтому приложение и бот
не могут разойтись в правилах.

**Доступ.** Каждый запрос от мини-аппа несёт подписанные Telegram данные о входе.
Worker пересчитывает подпись токеном бота и ищет вошедшего среди тех,
кто активировал код приглашения.
Подделать не получится, не зная токена; устаревшие данные (старше суток)
не принимаются. Вебхук защищён секретом, который выводится из того же
токена: его знают только Telegram и Worker, а задавать и хранить
отдельное значение не нужно. Если `WEBHOOK_SECRET` всё же задан
в настройках, используется он.

**Дубли.** У каждого контакта есть нормализованный ключ (`@ivan`, `t.me/ivan`
и `https://t.me/ivan/` дают `tg:ivan`), и ограничение в базе стоит на паре
«владелец + ключ»: дважды в своей базе человек не заведётся, а у разных
владельцев один и тот же эксперт — обычное дело. Люди без контакта
дублями друг друга не считаются.

**Утренняя сводка.** Cron будит Worker каждый час, и тот проходит по всем,
у кого сейчас наступил их собственный час сводки в их часовом поясе.
Отметка о последней отправке не даёт прислать её дважды.

**Обновление базы.** Схема приводится к текущей при первом обращении.
Переход с однопользовательской версии переносит все карточки и журнал
владельцу из `OWNER_ID` и переделывает ограничение на дубли — данные
при этом не теряются.

## Разработка

```bash
npm test          # быстрые проверки: разбор списков, подпись, сводка
npm run dev       # локальный запуск
npm run test:e2e  # сквозная проверка API и бота на локальном сервере
```

Для `npm run dev` и сквозных проверок скопируй `.dev.vars.example`
в `.dev.vars` и заполни. Локальная база создаётся сама.

Проверки в браузере (`npm run test:e2e:ui`) дополнительно требуют
`npm i -D playwright && npx playwright install chromium`.

# CRM в Telegram

Мини-апп внутри Telegram плюс бот, который ведёт базу потенциальных клиентов.
Можно кинуть боту список людей сообщением — они попадут в очередь «Кому написать».
Каждое утро бот сам напоминает, кому сегодня написать.

Всё живёт на Cloudflare Workers: одна программа отдаёт и страницу мини-аппа,
и принимает сообщения бота, и хранит базу. Бесплатного тарифа хватает с запасом.

## Что умеет

**Мини-апп** — две вкладки.

- **Кому написать** — все, кому ещё не отправлял первое сообщение,
  сгруппированы по источнику. Нажал «Написал» — человек уходит во вторую вкладку,
  а следующее касание назначается через 3 дня.
- **В работе** — план недели, кого коснуться сегодня, вся база с поиском и фильтрами.

**Бот**

- Пришли список сообщением — заведёт карточки и предложит отменить одной кнопкой.
- `/today` — просрочки, касания на сегодня, размер очереди, план недели.
- `/plan` — прогресс по недельным целям.
- Каждое утро присылает сводку сам.

**Формат списка** — один человек на строку:

```
Ахмад — @ahmad_arabic — преподаёт арабский
Иса | t.me/isa_coach | тренер по борьбе
@yusuf_finance
Марьям — нутрициолог
```

Разделители: тире, `|`, `;`. Порядок «имя — контакт — ниша» не обязателен:
ссылка и `@ник` узнаются в любом месте строки. Если в строке только ник —
он же станет именем. Повторы отсеиваются: `@ivan`, `t.me/ivan` и
`https://t.me/ivan/` — один и тот же человек.

## Установка

Понадобится [Node.js](https://nodejs.org) 20 или новее и аккаунт
[Cloudflare](https://dash.cloudflare.com/sign-up) — оба бесплатны.

### 1. Заведи бота

Напиши [@BotFather](https://t.me/BotFather) команду `/newbot`, придумай имя.
В ответ придёт **токен** вида `123456789:AAF...` — он понадобится дальше.

### 2. Узнай свой Telegram ID

Напиши [@userinfobot](https://t.me/userinfobot) — он ответит числом вроде `284729103`.
Это твой ID: по нему CRM пустит только тебя.

### 3. Поставь зависимости

```bash
git clone https://github.com/NeuroNedin/aqillych.git
cd aqillych
npm install
npx wrangler login
```

Последняя команда откроет браузер — разреши доступ к своему Cloudflare.

### 4. Создай базу

```bash
npx wrangler d1 create crm
```

Команда напечатает строку `database_id = "..."`. Скопируй этот id
в `wrangler.toml`, в самый низ — вместо нулей.

Затем создай таблицы:

```bash
npm run db:init
```

### 5. Положи секреты

```bash
npx wrangler secret put BOT_TOKEN        # токен от BotFather
npx wrangler secret put OWNER_ID         # твой Telegram ID
npx wrangler secret put WEBHOOK_SECRET   # длинная случайная строка
```

Для третьего можно сгенерировать строку:

```bash
openssl rand -hex 32
```

Сохрани её — она понадобится на шаге 7.

### 6. Выложи

```bash
npm run deploy
```

В конце команда напечатает адрес вида
`https://aqillych-crm.твой-логин.workers.dev` — скопируй его.

### 7. Подключи бота

```bash
BOT_TOKEN=токен \
WEBHOOK_SECRET=строка-из-шага-5 \
APP_URL=адрес-из-шага-6 \
npm run bot:setup
```

Эта команда говорит Telegram, куда слать сообщения, ставит команды в меню
и вешает кнопку «CRM» рядом с полем ввода.

### 8. Проверь

Напиши боту `/start`. Должно прийти приветствие с кнопкой «Открыть CRM».
Пришли ему пару строк со списком — они появятся в приложении.

## Настройки

В `wrangler.toml`, блок `[vars]`. После изменения — `npm run deploy`.

| Переменная    | Что значит | По умолчанию |
|---------------|------------|--------------|
| `TZ_OFFSET`   | Часовой пояс в минутах от UTC. Ташкент — `300`, Москва — `180`, Алматы — `300`. От него зависит, что считается «сегодня» | `300` |
| `DIGEST_HOUR` | Час утренней сводки по твоему времени, 0–23 | `9` |
| `APP_URL`     | Адрес мини-аппа. Обычно пусто: Worker запоминает свой адрес сам | пусто |

Недельные цели (партнёры 3, холодные 30, созвоны 2, предоплаты 1),
статусы, источники и «следующее касание через 3 дня» лежат в `src/domain.js` —
правь там, они разом поменяются и в приложении, и в боте.

## Как устроено

```
src/
  index.js    маршруты: API мини-аппа, вебхук бота, ежечасный cron
  auth.js     проверка подписи Telegram — без неё в базу не пустят
  bot.js      разбор сообщений, тексты ответов, утренняя сводка
  db.js       запросы к базе и проверка всего, что в неё кладут
  parse.js    разбор списков и приведение контактов к единому виду
  domain.js   статусы, источники, цели недели, работа с датами
public/
  index.html  страница мини-аппа
  app.js      её логика
schema.sql    таблицы
```

Мини-апп сам ничего не решает: сервер отдаёт ему готовые данные вместе
со словарями статусов и ссылками на контакты. Поэтому приложение и бот
не могут разойтись в правилах.

**Доступ.** Каждый запрос от мини-аппа несёт подписанные Telegram данные о входе.
Worker пересчитывает подпись токеном бота и сверяет id с `OWNER_ID`.
Подделать не получится, не зная токена; устаревшие данные (старше суток)
не принимаются. Вебхук защищён отдельным секретом, который знают
только Telegram и Worker.

**Дубли.** У каждого контакта есть нормализованный ключ (`@ivan`, `t.me/ivan`
и `https://t.me/ivan/` дают `tg:ivan`), на нём стоит ограничение в базе.
Люди без контакта дублями друг друга не считаются.

**Утренняя сводка.** Cron будит Worker каждый час, тот смотрит на
`DIGEST_HOUR` и отметку о последней отправке — так сводка уходит
один раз в день и не задваивается.

## Разработка

```bash
npm test          # быстрые проверки: разбор списков, подпись, сводка
npm run dev       # локальный запуск
npm run test:e2e  # сквозная проверка API и бота на локальном сервере
```

Для `npm run dev` и сквозных проверок скопируй `.dev.vars.example`
в `.dev.vars` и заполни. Локальную базу создаёт `npm run db:init:local`.

Проверки в браузере (`npm run test:e2e:ui`) дополнительно требуют
`npm i -D playwright && npx playwright install chromium`.
